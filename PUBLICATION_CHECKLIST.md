# Publication checklist

Complete the local checks first. The final section intentionally requires the future GitHub owner and is not performed by repository automation.

## Local repository

- [x] Add an OSI-compatible Apache-2.0 license.
- [x] Add contribution, conduct, security, architecture, privacy, and self-hosting guidance.
- [x] Keep `.env` files, runtime metadata, build output, and local logs untracked.
- [x] Replace the tracked personal Tailscale hostname with automatic detection and configuration variables.
- [x] Add reproducible install, CI, browser audit, and dependency update configuration.
- [x] Scan the original history with Gitleaks before rewriting it; no credential leaks were detected.
- [x] Replace the pre-publication history with a clean initial commit and keep a complete backup outside the repository.
- [x] Attribute the clean history to the maintainer's public GitHub identity using a GitHub noreply address.
- [x] Run npm audit, OSV-Scanner, Semgrep, Gitleaks, TruffleHog, ShellCheck, and Actionlint; resolve actionable findings.
- [x] Validate Supabase ownership, RLS, RPC-only writes, profile column privileges, project-version owner consistency, payload constraints, quotas, and version retention against PostgreSQL.

## GitHub repository settings

- [x] Create a private staging repository, add `origin`, and push the reviewed clean history.
- [ ] Change the repository visibility to public only after explicit maintainer review.
- [x] Set a concise description and project topics; leave the homepage unset until a dedicated demo origin is selected.
- [x] Enable Issues.
- [ ] Enable private vulnerability reporting after the repository becomes public.
- [x] Enable the dependency graph, Dependabot alerts, and Dependabot security updates.
- [ ] Enable secret scanning and push protection after the repository becomes public.
- [ ] Protect `main` with required CI status checks and disabled force pushes when the repository plan permits it.
- [x] Review the Community Standards profile and confirm a 100% health score.
- [x] Confirm the repository owner's public profile and GitHub-attributed noreply commit email identify the maintainer accurately.
- [x] Publish a private contact route for conduct reports before the repository becomes public.

## First release and Codex for OSS evidence

- [x] Add sanitized 2D, 3D, and mobile screenshots generated by the browser audit.
- [ ] Select a dedicated demo origin and a header-capable host or edge proxy; plain GitHub.com Pages cannot enforce the required per-site response headers. Deploy only after the repository is public and the edge is configured.
- [ ] Scan the deployed origin with a header/CSP analyzer and fix actionable findings.
- [x] Prepare a private draft `v1.0.0` release with release notes and verification evidence.
- [ ] Publish the draft release only after the repository becomes public.
- [x] Create labeled roadmap issues, including a documented `good first issue`.
- [ ] Triage real issues, review pull requests, and maintain a visible release cadence.
- [ ] Record honest adoption signals such as stars, forks, active installations, external contributors, and references.
- [ ] Prepare the OpenAI organization ID and a concrete API-credit plan for issue triage, pull request review, testing, security review, and release maintenance.
